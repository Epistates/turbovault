# Migrating to TurboVault 4.0

TurboVault 4.0 consolidates the MCP tool surface from 79 tools to 52, counting the new `validate_vault`. Tools that answered the same question in different ways are now one tool with a parameter that picks the variant, following Anthropic's guidance on [writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents): fewer, workflow-shaped tools are easier for an agent to choose between, and the catalog an agent loads is smaller.

Three other changes affect every client:

- **Every vault-scoped tool takes an optional `vault` argument** naming the registered vault the call runs against. Without it the call uses the active vault, as before. Naming a vault doesn't change the active one, so concurrent sessions (and stateless clients) no longer depend on one global active vault. The tools that manage the registry (`list_vaults`, `add_vault`, `remove_vault`, `set_active_vault`), `get_ofm_guide` and `list_orphan_fanouts` (which has its own `vault`) don't take it. An unknown name is refused with the names that are registered.
- **`tools/list` shows the core tools by default.** 22 advanced tools are left out of the listing but stay callable by name: `remove_vault`, `move_file`, `diff_notes`, `compare_notes`, `find_duplicates`, `suggest_links`, `note_quality`, `find_stale_notes`, `analyze_grounding`, `okf_validate`, `generate_index`, `append_log_entry`, `visualize`, `export`, `audit_log`, `rollback_preview`, `rollback_note`, `fanout`, `list_orphan_fanouts`, `find_notes_from_template`, `inspect_frontmatter` and `query_frontmatter_sql`. `--show-advanced-tools`, `TURBOVAULT_SHOW_ADVANCED_TOOLS=1` or `tool_visibility.show_advanced_tools: true` lists them all; an `allowed` list lists whatever it names.
- **No merged tool mixes reading and writing**, so every tool's `readOnlyHint` and `destructiveHint` describe all of what it does. `manage_tags` used to list tags too; listing moved to `get_notes_info`.

## Response shapes

- `list_vaults` returns `{active_vault, vaults, config}` rather than a bare array of vaults.
- `graph_report` returns `{kind, items}`; `items` has the shape of the kind asked for.
- `audit_log` returns its entries as before, or the statistics object with `summary: true`.
- `note_quality` and `analyze_grounding` return one note's result with `path`, the vault-wide result without.
- `compare_notes` adds `link_strength` to the content comparison.

Every shape is in the tool's `outputSchema`.
